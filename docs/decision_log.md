## Future enhancements

- **A. Keyword-index whole tables.** Add the table's rows (`context`) to `fts` for table chunks. Free; a migration. Only keyword search improves, and long numeric tables may crowd keyword results.
- **B. Summaries that name the row items** (e.g. "Adverse reactions in ≥5% of patients: nausea, vomiting, diarrhea…", still no numbers). ~$0.30 to re-summarize 1,455 tables and re-embed. Improves keyword and dense search and keeps chunks short. Preferred. Note: the spec's Definition of done requires `search("nausea", content_types=["table"])` to return label adverse-reaction tables, which this fixes. Check on 2026-10-04: 20 of 81 label adverse-reaction rows appear only in tables (Saxenda 10, Wegovy 7, Zepbound 3). For 11 such questions ("How often did dizziness occur with Zepbound?") the table reached the top 20 in 9, but 6 of those at ranks 17–20, apparently as "that drug's adverse-reaction table" rather than by the row; Cohere also only sees caption + summary + header, so it can't see the row either. Deferred: common side effects work because the text repeats them; rarer ones are hit-or-miss.
- **C. Rerank 50 candidates in `answer_question` (spec: 20).** After the trial labels, the main SURMOUNT-1 result is hybrid rank 31; reranking 50 put it at #2 (score 0.987). Still one Cohere call; rerank time ~0.7 s → 1.2 s. **Adopted 2026-10-06** (see the table row above): dev recall@10 67.9% → 85.7%, numeric_fact 50% → 100%.
- **D. Put each trial's acronym in its ClinicalTrials.gov chunk header/content.** Found via golden q23 ("What BMI was required to enter STEP 1?", 2026-10-06): the STEP 1 registry record (`ctgov:NCT03548935`) is never retrieved. Its chunks are titled by the long official name ("Effect and Safety of Semaglutide 2.4 mg…"); "STEP 1" lives only in `metadata.acronym`, so keyword search can't match it and its generic eligibility text ("BMI ≥30…") is lost among 313 other registry Eligibility chunks. Papers already carry a trial label in their header (row 27 above) but the registry records do not. Fix: add the acronym to the ctgov chunk header (a re-chunk + re-embed of the ~720 registry records). Would let acronym + attribute questions ("STEP 1 BMI", "SURMOUNT-2 enrollment") find the record itself.
